# Release Plan: v0.3.0

> **Status:** Release in progress; draft awaiting Windows test
> **Branch:** `dev`
> **Target:** `main`
> **Last updated:** 2026-11-09

## Scope

Release the current `dev` line as **v0.3.0**. The version in `pyproject.toml` is already
`0.3.0`; this release does not need another version bump.

Included since `v0.2.2`:

- Per-playlist audio copy workflows in the CLI and GUI, with numbering, overwrite, and
  missing-file handling.
- Portable copied exports with playlist files in the output root.
- NML paths are volume-relative (`ADR-0009`), fixing empty/relocating Traktor playlists.
- GUI export UX: locked controls, log view, bottom progress/cancel, return to the main tab
  after completion, and a compact About dialog linked from the version label.
- Optional `PLAYLISTS/<FORMAT>` layout with shared audio (`ADR-0010`).
- Format-suffix label/tooltip fixes and M3U extended-format clarification.
- Versioned Windows release executables with `jaunmatrin` publisher metadata
  (`ADR-0012`).
- Copied NML exports on Windows keep the output folder in `LOCATION`/`PRIMARYKEY`
  (`ADR-0013`).
- CI: macOS 15 Intel/arm64 runners and Windows test execution.

Not included:

- OneLibrary/`exportLibrary.db` support. This is the next endeavor and remains tracked in
  [onelibrary-support.md](onelibrary-support.md). Legacy PDB playlists can still be
  incomplete until that lands.
- Code signing/notarization. Windows publisher metadata is present, but SmartScreen still
  shows “Unknown Publisher” until the executables are Authenticode-signed. See
  [code-signing.md](code-signing.md).

## Release steps

1. Merge the release PR into `main`.
2. Confirm `main` contains `pyproject.toml` version `0.3.0`.
3. Move the `v0.3.0` tag to the release commit.
4. Build macOS locally with `./build.sh --both`; the x64 DMG remains the last successful
   CI artifact unless an Intel Mac rebuild is available.
5. Build Windows locally with `.\build.ps1 -Both` and upload the versioned executables to
   the draft release.
6. Update the draft release body from
   [`docs/releases/v0.3.0.md`](../releases/v0.3.0.md), test the assets, and publish.
7. If anything is wrong, delete the tag and draft release before publishing.

## Notes

- macOS builds are unsigned; Gatekeeper may warn on other machines.
- Windows binaries are unsigned. File properties show `jaunmatrin`, but SmartScreen still
  warns until a trusted Authenticode certificate is used.
- GitHub Actions is currently blocked by a billing issue. Local builds and manual
  `gh release upload` are the reliable path.
- The draft release body comes from
  [`docs/releases/v0.3.0.md`](../releases/v0.3.0.md), not the raw commit log. See
  [ADR-0011](../adr/0011-release-notes.md).
- OneLibrary support should be planned as the next major parser change, not bundled into
  this release.

# ADR-0005: Kaitai Generated Code

- **Status:** Accepted
- **Date:** 2026-10-29
- **Related:** [`parsing.md`](../agents/parsing.md#kaitai-regeneration), [`pitfalls.md`](../agents/pitfalls.md#kaitai-regeneration)
- **Supersedes:** —

## Context

`src/universal_dj_usb/kaitai/rekordbox_pdb.py` and `rekordbox_anlz.py` are generated by
Kaitai Struct. The parser imports `RekordboxPdb` from the generated module.

The regeneration path is currently broken or undocumented:

- `scripts/update_kaitai.sh` writes to `src/universal_dj_usb/pdb_parser/`, while imports
  use `src/universal_dj_usb/kaitai/`.
- The current `external/rekordcrate` checkout (v0.3.0-23-g9ab517e) contains no `.ksy`
  files; the script warns that rekordcrate may not ship them and points to
  Deep-Symmetry/dysentery.
- The script requires `kaitai-struct-compiler`.

## Decision

1. Treat generated Kaitai files as **read-only**. Never hand-edit
   `rekordbox_pdb.py` or `rekordbox_anlz.py`.
2. Parser behavior changes belong in `parser.py`, not in generated code.
3. Do not run `scripts/update_kaitai.sh` as if it works until the source path and output
   directory are fixed and verified.
4. Before changing the PDB schema or regenerating, document the canonical `.ksy` source
   (vendored file or external repository commit) and add a test that parses a known
   synthetic PDB.
5. Update this ADR (or supersede it) when the regeneration path is resolved.

## Consequences

- Parser fixes are limited to the Python wrapper until regeneration is fixed.
- A future agent may need to re-create the `.ksy` source from the generated file header
  and the Deep-Symmetry/dysentery project.
- The generated files remain trustworthy as the current runtime contract, but their
  provenance is not reproducible from this checkout.

## Alternatives considered

- **Hand-edit generated files.** Rejected: changes are lost on regeneration and obscure
  the schema.
- **Delete the generated files and depend on a runtime generator.** Rejected: adds a build
  dependency and complicates packaging.
- **Vendor `.ksy` files into the repo now.** Possible future fix, but it requires
  licensing/provenance review and a regeneration test.

## Evidence

- Header of `src/universal_dj_usb/kaitai/rekordbox_pdb.py`
- `scripts/update_kaitai.sh` (output path and `.ksy` discovery)
- `external/rekordcrate` submodule at `9ab517e`
